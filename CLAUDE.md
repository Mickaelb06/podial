## Features done
Podcasts (Top 10 by country/genre, search, subscribe), radios by country + city (de-duplicated), YouTube audio (desktop, optional, via yt-dlp), offline downloads with cancel, automatic downloads (Linux, off by default), covers kept offline, sleep timer (minutes/hours/end of episode, fade-out), played-episode tracking, new-episode badges + hourly check + notifications, About dialog, update check (GitHub latest release; opt-in on Linux), preferences dialog (menu ≡), launch at login (all desktop versions), right-click menu on the top-bar pill (open/quit), animated GNOME top-bar player, 7 UI languages incl. RTL on Linux, Android Auto browse tree, quotes + published transcripts (podcast:transcript; Android, desktop GTK and Compose), Android home-screen widgets (compact + spinning vinyl), world map for radios with real-time day/night (data `shared/data/world.json`, Natural Earth 110m, generated by `desktop/tools/make_world.py`; GTK draws it with Gsk.PathBuilder, no cairo dependency), Android notification for new app versions, redesigned Android radio page/player (now playing from ICY metadata), RTL schedule on Android (`shared/.../Programs.kt`, scraped from rtl.fr; no common source for other stations). "Surprise me" dice button on the radios page (random country with radios, then random station; `shared/.../Surprise.kt`, Android + Compose + GTK `surprise_radio` + web), quote shared as a 1080x1350 image card (Android `QuoteCard.kt`, via FileProvider; layout checked with Robolectric native graphics, not kept in the repo), shareable links on the web page (`app/#r=<radio-browser uuid or extra-id>` / `#p=<iTunes id>`, set by `syncHash`, read by `loadFromHash`).

- Extra radios missing from radio-browser (e.g. RMC 2 = Radio Monte Carlo 2, Italy, stream read from its own site): same list in `shared/.../Extras.kt`, `desktop/catalog.py` (`EXTRA_RADIOS`) and `docs/app/index.html` (`EXTRA_RADIOS`); keep the three identical. Shown in their country's list and in any search that matches their name.
- Podcast catalog data `shared/data/podcast_sources.json` (source of truth; copy with `desktop/tools/sync_sources.sh` to `desktop/`, `docs/app/` and `~/podial/`; `SourcesTest` fails if the copies differ): all 110 Apple genres/sub-genres with names in en/fr/es/de/pt (from `itunes.apple.com/WebObjects/MZStoreServices.woa/ws/genres?id=26&cc=XX`), ~120 radios/publishers in 20 countries (`artistId` when Apple gives one, otherwise looked up by exact name, max 100), and the local-flash radios (ICI, Alouette, K6FM). UI: chips row 1 = All / Radios / Local news / top-level genres, row 2 = sub-genres of the chosen genre (Android, Compose, GTK `GenreBar`, web).
- **Apple API quirks** (checked 2026-10): (1) `feedUrl` is missing for France Inter/Radio France podcasts and a few others: they used to be silently dropped, now kept with the pending feed `itunes:<collectionId>` and resolved at open time from the `"feedUrl"` in `https://podcasts.apple.com/<cc>/podcast/id<ID>` (`Api.resolveFeed`, `catalog.resolve_feed`, cached); the web page cannot do that (CORS), so it shows "open it in the app". (2) The **search** endpoint is rate-limited (~20/min per IP, then HTTP 403 for tens of minutes) while lookup and the chart RSS are not: never loop on search; pace scripts at 4 s+ and back off. (3) Many publishers have no `artistId` in results (Sud Radio, Skyrock, Alouette, Mediapart…). (4) `lookup?id=<artistId>&entity=podcast&limit=200` gives up to 200 podcasts; `search?attribute=artistTerm` only 100. (5) Always pass `country=` to lookup: some podcasts exist only in one store. (6) `rss.marketingtools.apple.com` is flaky (timeouts), the chart is now read from `itunes.apple.com/<cc>/rss/toppodcasts/limit=N[/genre=G]/json` first.
- Episode list filters on podcast pages: sort newest/oldest by publication date + filter all / downloaded / unfinished (= not marked played). Shared logic `shared/.../EpisodeList.kt` (Android, Compose; falls back to feed order if a date is unreadable), Python `catalog.filter_episodes` (episodes carry a `ts`), web page (sort + unfinished only, no downloads there).
- Radio logos: `Api.radios` merges duplicate names to keep a logo, then `Logos.fill` fixes Wikimedia thumbnail sizes (330px), checks that each logo URL really returns an image (dead ones, 404/403, are dropped; 429/5xx are not remembered) and reads the station's own homepage (apple-touch-icon / icon) for the rest; cached in `java.io.tmpdir/podial-logos.json`. On the FR top 60: 55 logos, 0 dead (was 37). Linux and the web page only fix the Wikimedia size (`fix_logo_url` / `fixLogo`).

## How to build and test
- Linux app: `cd ~/podial && ./install.sh` (builds translations, installs the extension atomically) then `python3 podial.py`. `--background` starts without a window.
- **Tool/OS pitfalls on this machine (7 GB RAM)**: run Gradle in the background and poll (`setsid nohup … &`), never two builds at once, `--no-daemon`; a foreground build can get the shell OOM-killed (exit 137). Gradle: `~/Android/gradle-8.10.2/bin/gradle` or each project's `./gradlew`, `ANDROID_HOME=~/Android`, JDK 17 (sdkman).
- Android: `cd android && ANDROID_HOME=~/Android ./gradlew :app:assembleDebug` (or `assembleRelease`: signs with `~/.podial-signing/keystore.properties`).
- compose-desktop: `./gradlew :compileKotlin`, `./gradlew run`. Headless run for screenshots: `xvfb-run -s "-screen 0 1280x800x24 -fbdir DIR" env SKIKO_RENDER_API=SOFTWARE ./gradlew run`, then convert `DIR/Xvfb_screen0` (XWD) with a small PIL script.
- GNOME screenshots: run an isolated headless shell: `dbus-run-session -- gnome-shell --headless --wayland --wayland-display wayland-pbtest --virtual-monitor 1366x768 --no-x11 --unsafe-mode`, drive the app with a Python script (GLib timeouts calling Window methods), screenshot via `org.gnome.Shell.Screenshot`, clear notifications first with `Main.messageTray.getSources().forEach(s => s.destroy())` through `org.gnome.Shell.Eval` (a real notification shows the owner's e-mail). Use `XDG_DATA_HOME=<temp>` so tests don't touch the real library. Screenshots of the real session are denied.
- **Isolated GNOME Shell tests must use their own `XDG_RUNTIME_DIR`** (e.g. `XDG_RUNTIME_DIR=$(mktemp -d)` with mode 700) and `GSETTINGS_BACKEND=memory`: a shell creates `$XDG_RUNTIME_DIR/gnome-shell-disable-extensions` at start and removes it once started; if the file is left behind, the owner's real session at its next login treats it as a crash and sets `org.gnome.shell disable-user-extensions true`, which silently hides the Podial pill. Fix: `gsettings set org.gnome.shell disable-user-extensions false` (applies live). After any shell test, check `gsettings get org.gnome.shell disable-user-extensions`.
- Landing page preview: `google-chrome --headless=new --no-sandbox --screenshot=out.png --window-size=1280,3900 file://…/docs/index.html`.
- `pkill -f 'podial[.]py$'` kills the app; a plain `pkill -f podial.py` inside a Bash command kills the Bash call itself (exit 144), so use the bracket trick and keep it in its own call.
- `~/podial` is the source of truth for `desktop/`: rsync only goes `~/podial` → repo. Version bumps and fixes made directly in the repo's `desktop/` get overwritten by the next rsync, so make them in `~/podial` too (or `cp` the file back). Never `cp` a repo file over `~/podial` without diffing first.
- PyGObject on this machine has no `gi._gi_cairo` (no `python3-gi-cairo`): don't use cairo drawing in the GTK app (the world map uses Gsk.PathBuilder / Gtk.Snapshot, GTK >= 4.14).
- GTK tests under Xvfb: run the app inside `dbus-run-session` (otherwise it activates the user's real Podial instance over D-Bus), wait ~20 s for startup, and in RTL languages the window is placed at x<0 (move it with XMoveWindow via ctypes).
- Never overwrite `.mo` files in place while GNOME Shell runs (it mmaps them and shows garbage); copy to a temp name then `mv` (install.sh and build_translations.py already do).
- New UI texts: add the msgid to every `po/*.po` and `po/podial.pot`, run `tools/build_translations.py`.

## Release process (the owner runs the git commands himself)
1. Bump the version everywhere: `desktop/catalog.py` (and the same file in `~/podial`), `android/app/build.gradle.kts` (`versionName` + `versionCode`), `compose-desktop` (`APP_VERSION`, `packageVersion`; macOS = 1.0.x), CLAUDE.md, and the download links in `README.md`, `README.fr.md`, `docs/index.html`, `docs/app/index.html` (`REL` + file names in the left menu) (they point to `releases/download/vX.Y.Z/<file>`, because `releases/latest` ignores pre-releases).
2. Build the signed APK locally (`assembleRelease`), copy it to `~/podial-launch/podial-android.apk`, install it on his phone, commit locally.
3. He runs `git push`, then `git tag vX.Y.Z && git push origin vX.Y.Z`; the `Release` workflow (15-20 min) attaches .deb, .rpm, .tar.gz, .exe, .msi, .dmg, .apk. Check with `curl https://api.github.com/repos/Mickaelb06/podial/releases`.
4. The apps' update check reads the releases list (pre-releases included); Android also notifies once per new version (hourly `CheckWorker`).

## Feature notes
- Quotes/transcripts: `shared/.../Transcript.kt` (SRT/VTT/JSON/HTML/text, `Quote`), feed tag `podcast:transcript` parsed in `Api.parseFeed` and `catalog.fetch_feed`; transcripts cached on disk; quotes stored locally (Android prefs, desktop JSON, GTK `quotes.json`). Test feed with transcripts: https://feeds.podcastindex.org/pc20.xml (needs a browser User-Agent).
- Android widgets: `Widgets.kt` (RemoteViews, driven by the playback service; vinyl spin = indeterminate ProgressBar with a rotate drawable).
- World map: shared Compose `WorldMap.kt`/`World.kt`/`Sun.kt` + `shared/data/world.json`; GTK `desktop/worldmap.py` (Gsk path, no cairo). Day/night uses the real sun position, refreshed every minute.
- GNOME extension: never recurse from `ease` `onComplete` (it completes synchronously when the pill is unmapped, e.g. screen locked, causing "too much recursion"); use `_later()`. Test the extension in an isolated headless shell (see above) with a playing app; Wayland needs a re-login to reload the extension in the real session.

## Resuming after a PC restart
1. On login GNOME loads the `podial@podial.app` extension (it is in `enabled-extensions`); the top-bar pill appears when Podial plays. This also fixes the garbled texts seen before the restart.
2. Start the app: `cd ~/podial && python3 podial.py` (the old env vars `PODIAL_EXTRA_MPRIS_NAMES` / `PODIAL_NO_TRAY` were only a workaround for the previous extension; no longer needed). Or enable "Launch at login" in Preferences.
3. Open Claude Code in `~/podial-repo` so this file is read. `git status` / `git log origin/main..` shows what is not pushed yet.
4. Background Gradle/Xvfb/Chrome processes from earlier sessions disappear on reboot; nothing else to clean up.
